## Style and Structure of README.md file

### Style

If you ever need to modify this file take care of the following:

- Do not use emojis anywhere.
- Retain a serious, but friendly style without becoming either pompous or too casual.
- No verbalism. The writing style should be straightforward and comprehensible.

### Structure

Always include (or retain, if present) the following sections:

- Title: the name of the app or project and its current version. I will provide that myself.

- Description: a short summary of the project's purpose, functionality and general characteristics.

- Screenshot: provide the boilerplate Markdown code so I can copy-paste the image or gif myself.

- New Features: a bullet point list of the most important new features added in the current version. Attach the version number from the title next to the section's title (e.g., New Features (v1.4)).

- Tech stack: a bullet point list of the more important technologies used in the project's construction. Use `shields.io` badges wherever possible.

- Learning Goals: a short section with bullet points giving a list of abilities, knowledge, concepts, workflows, etc. I hope to attain with this project. Leave it blank, so I can write it myself.

- Areas for improvement: a short summary of some areas that the project could be improved. Draw them from `docs/to_improve.md`. Ommit section if that file is empty or non-existent.

- How to run: instructions on how to run and test the project. If the project is a website, provide only a placeholder for the url link.

- Troubleshooting: optional section with material concerning troubleshooting. Draw it from `docs/troubleshooting.md`. Ommit section if that file is empty or missing.

- Future Goals: a short summary (one or two sentences the most) of the next project goals. Use the item in the line beginning with `NEXT: ` in `docs/progress.md` for that.

- To Fix: a bullet point list of bugs to fix. Draw them from `docs/to_fix.md`.

- Insights: include the following text verbatim:

'Check the docs folder for interesting material concerning this project, like the problems I faced during its construction, skills I learned or improved, areas I hope to improve in the future, and general realizations or thoughts I had during this project.'
